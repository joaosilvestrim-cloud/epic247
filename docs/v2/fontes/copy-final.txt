32. REGRAS DE TOM PARA MICROCOPY


Usar:
“Não conseguimos concluir.”
“Confira e tente novamente.”
“Seu resultado está pronto.”
“Você pode continuar depois.”
“Pagamento confirmado.”


Evitar:
“Ops!” em contexto financeiro ou sensível.
“Erro fatal.”
“Você fez algo errado.”
“Diagnóstico concluído.”
“Parabéns!” automaticamente depois de qualquer resultado ou compra.
“Última chance” quando não for literalmente verdadeira.
“Só hoje” sem condição comercial real.


33. REGRAS TÉCNICAS DE IMPLEMENTAÇÃO


• mensagens dinâmicas devem vir de chaves reutilizáveis, não hardcode repetido em cada página;
• erro de campo deve estar associado programaticamente ao respectivo input;
• mensagens assíncronas importantes devem ser anunciadas de forma acessível na interface;
• estados de pagamento devem ser derivados do status interno normalizado após integração com Kiwify;
• retorno do checkout não substitui webhook/confirmação operacional;
• nenhum texto deve revelar IDs internos, tokens, payloads, respostas de Mapas ou detalhes técnicos;
• eventos de erro podem carregar código técnico internamente, mas a mensagem pública deve permanecer humana;
• CTAs para produtos já comprados devem mudar de compra para acesso sempre que a identidade puder ser reconhecida.
